# Device integration notes

The apply scripts generate everything under `vendor/wraithlink/` in the source tree.
Two manual wire-ups remain in the device/product config (kept manual because they touch
signed/policy-sensitive areas):

## 1. Inherit the WraithLink product makefile

In the device product config for your target (e.g. the `tokay` product `.mk`), add:

```make
$(call inherit-product, vendor/wraithlink/wraithlink.mk)
```

`wraithlink.mk` is generated by `scripts/04-apply-rebrand.sh` and `include`s every
`wraithlink-*.mk` fragment (network privacy, apps, first-boot, X47).

## 2. SELinux domain for the first-boot service

The oneshot `wraithlink_firstboot` service runs `settings` and `pm`. Add a minimal
domain so it is allowed under a `user` (enforcing) build. Sketch:

```
# sepolicy/private/wraithlink_firstboot.te
type wraithlink_firstboot, domain;
type wraithlink_firstboot_exec, exec_type, file_type, system_file_type;
init_daemon_domain(wraithlink_firstboot)
# allow the narrow set of settings/pm calls it needs; keep this tight.
```

Never grant broad permissions here; scope to exactly what the fragments call.

## 3. On-device Linux (rebranded AVF Terminal)

Pixel 8+ support the Android Virtualization Framework. GrapheneOS ships a Terminal app
that boots a Debian pVM. WraithLink rebrands it to "WraithLink Terminal" via the standard
rebrand pass; enable the AVF/Terminal product packages for the target. See
`docs/on-device-linux.md`.

`04-apply-rebrand` (rebrand + overlays) -> `05-build` -> `06-generate-release`.
