Security model

This page is the one to read before you trust WraithLink with anything that matters. It describes what WraithLink actually defends against, how, and - just as important - where it stops.

Threats WraithLink is built for

  • Theft of a powered-off or locked phone. Full-disk encryption keyed to your lock credential, enforced by the secure element with attempt throttling. Standard, and strong.
  • Seizure where you can act. A panic credential destroys the device's encryption keys outright. Because the keys are killed first, the data is unrecoverable even if the process is interrupted a second later.
  • Coercion to unlock (milestone 2). A decoy PIN that opens the everyday phone while silently destroying WraithVault — separate from panic wipe. Lean published images keep it off until hardware QA; it is coercion UI cover, not forensic deniability.
  • Network surveillance. Optional Mullvad encrypted DNS from Setup, GrapheneOS per-connection MAC randomization, and 2G disable guidance.
  • Opportunistic physical access. USB data blocked while locked, ADB off by default, auto-reboot back to a keys-evicted state after idle, auto-wipe after repeated wrong attempts.
  • Remote exploitation. The upstream exploit mitigations and hardened memory allocator are preserved, the attack surface is trimmed, and heavy tooling is kept off the phone entirely (see X47 pairing).

The ceiling, stated plainly

No forensic-grade deniability in software. If an adversary images your storage before you ever enter a PIN — the way a well-equipped lab or border unit works — nothing you type afterwards undoes that copy. Use the panic wipe when you can still act. WraithVault is a normal secondary user profile and is detectable; decoy PIN only drops that profile after unlock — it does not claim UI hiding or deniable storage.

What we deliberately did not change

WraithLink keeps verified boot, hardware attestation, and the upstream package identifiers intact. Renaming internal package IDs or defeating attestation to look "less like GrapheneOS" would break the WebView/browser wiring and, worse, weaken the very integrity guarantees that make the duress feature meaningful. The rebrand is user-facing only.

Trusting the build

WraithLink is signed with its own release key and relocks the bootloader against it, so the phone will refuse to boot a system image that isn't WraithLink's. Factory images published on this site carry a SHA-256 checksum, and the web installer verifies it in your browser before writing anything. Always check the checksum against the release.
